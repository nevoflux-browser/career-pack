# Career — Writing Contract

Governs every piece of text a human will read or send: outreach messages,
report prose, and CV/PDF copy. Read `conventions/rules.md` first — in
particular **never invent** experience or metrics (read them from `career/cv` /
`career/article-digest`) and **never include a phone number** in generated text.

## Tone calibration

- **Direct and specific.** Lead with the concrete point; no throat-clearing.
- **No corporate-speak, no clichés.** Ban "passionate about", "results-driven",
  "team player", "fast-paced environment", "wear many hats".
- **Earn the reply / the read.** Every message should give the reader a reason to
  respond that a generic template wouldn't. If a sentence would fit any candidate
  applying to any role, cut or replace it.
- **No filler** (`rules.md`). Prefer one strong proof point over three weak ones.
- **Honest register.** Confidence from evidence, never invented superlatives.

## ATS rules (CV / PDF copy)

For any text destined for a résumé or an applicant-tracking system:

- **Mirror the JD's vocabulary** for real skills the user has — match the exact
  term the posting uses (e.g. "LLM evaluation" vs "model eval") when the CV
  supports it. Never add a keyword the CV can't back up.
- **Plain, parseable structure** — standard section headings, no text in images,
  no multi-column layouts that break ATS extraction, no tables for core content.
- **Front-load evidence** — quantified outcomes first, tools/stack second.
- **One artifact, tailored** — tailor to the JD's must-haves (Block B); don't ship
  a generic CV.

## Language

- **Default English.** Otherwise write in the **language of the JD**
  (`rules.md`): a Spanish posting gets Spanish copy.
- For outreach to a Spanish-language company, provide **both** an EN and an ES
  version.

## Length limits

- **LinkedIn connection request: ≤ 300 characters** (hard limit — career-contacto
  messages must fit).
- Outreach body: the 3-sentence framework in career-contacto (hook → proof →
  CTA); brevity beats completeness.
- Report prose: tables and bullets over paragraphs; a hiring decision, not an essay.

## Red lines (from `conventions/rules.md`)

- Never invent experience, metrics, or proof points — cite the user's sources.
- Never include the user's phone number in any generated message.
- Never send anything — every skill drafts; the human reviews and sends.
- Never recommend compensation below market rate.
